# 00 — Setup

Before the first program, a map of what we are building and how to run it.

## What is different from the blog

Sandler's compiler has four hand-written stages: a **lexer** that turns
source text into tokens, a **parser** that turns tokens into an
**abstract syntax tree** built from data types she defines, a **code
generator** that walks that tree and prints assembly, and a small **driver**
that calls `gcc` to assemble and link.

Here, the lexer, the parser, and the AST types are *generated by RTK* from a
single grammar file, `c.pg`. The code generator is still yours to write — but
instead of walking the tree with hand-written recursion and printing assembly
strings, it pattern-matches the tree with **quasi-quotation** and builds a
*second* AST, this one for the assembly language, described by a second
grammar, `asm.pg`. Only the final assembly-to-text step and the driver are
ordinary hand-written Haskell.

```
   file.c
     │
     │  CLexer.scanTokens          ┐ generated by RTK
     ▼                             │ from c.pg
   [ tokens ]                      │
     │  CParser.parseC             ┘
     ▼
   C AST          Program · Function · Statement · Exp · Ident
     │
     │  Codegen.codegen            ← you write: QQ patterns in,
     ▼                               asm AST built with splices out
   Asm AST        Asm · AsmItem · Operand · Reg · AsmId   (from asm.pg)
     │
     │  Emit.emit                  ← you write: asm AST → AT&T text
     ▼
   file.s
     │  gcc                        ← Main.hs driver
     ▼
   executable
```

The payoff of routing the output through `asm.pg` is that the assembly is a
real syntax tree you build with quasi-quotes (`[asmItems| movl $src, %eax |]`)
rather than a soup of string concatenations — and because RTK also generates
a *parser* for `asm.pg`, the emitter can be round-trip-tested for free.

## Prerequisites

A Haskell toolchain and a C toolchain:

- GHC ≥ 9.4 and Cabal ≥ 3.8
- [Alex](https://hackage.haskell.org/package/alex) and
  [Happy](https://hackage.haskell.org/package/happy) (RTK emits Alex lexers
  and Happy parsers)
- `gcc` (the driver shells out to it to assemble and link)

The repository's [`CLAUDE.md`](../../../CLAUDE.md) documents a verified setup
for a stock environment. The C compiler tutorial does **not** have its own
`.cabal` file: it borrows the toolchain from the RTK checkout two levels up
through `cabal exec`, which is why every command below runs from inside the
RTK tree.

## Build it

Build RTK itself first (it is what generates the front end), then the
tutorial:

```bash
# from the repository root
cabal build

cd tutorials/c-compiler
make build
```

`make build` runs RTK on both grammars and compiles the result:

- `rtk c.pg gen/` → `gen/CLexer.x`, `gen/CParser.y`, `gen/CQQ.hs`
- `rtk asm.pg gen/` → `gen/AsmLexer.x`, `gen/AsmParser.y`, `gen/AsmQQ.hs`
- Alex/Happy turn the `.x`/`.y` into Haskell, and GHC compiles everything
  together with `Main.hs`, `Codegen.hs`, and `Emit.hs` into the compiler
  binary, `ncc`, and the quasi-quotation test binary, `test-qq`.

Everything under `gen/` is generated and git-ignored; you never edit it.

## The driver contract

`ncc` follows the contract of Sandler's
[test suite](https://github.com/nlsandler/write_a_c_compiler):

```bash
./ncc path/to/program.c
```

- On a **valid** program it writes an executable named `program` next to the
  source (no extension) and exits 0.
- On an **invalid** program it prints an error, exits non-zero, and leaves no
  output files behind.

That is the whole interface. Stage by stage, "does it compile and does the
program exit with the right code" is the test.

## Test it

Two layers. The tutorial's own suite builds and runs everything in-tree:

```bash
make test
```

This runs `test-qq` (the quasi-quotation feature matrix, plus the
emit/parse round trip for the assembly grammar) and `run_tests.sh` (compiles
every program under `tests/valid` and `tests/invalid` and checks exit codes
against a `gcc`-built reference). The tail of a passing run:

```
PASS  round trip: parse (emit asm) == asm
PASS  full pipeline: parse C -> codegen -> emit -> parse Asm
PASS  tests/valid/return_2.c (exit code 2)
...
PASS  tests/invalid/no_semicolon.c (rejected)
All stage-1 compiler tests passed.
```

The second layer is Sandler's own suite, which is the real acceptance test.
Clone it once and point its driver at `ncc`:

```bash
git clone https://github.com/nlsandler/write_a_c_compiler /tmp/wacc
/tmp/wacc/test_compiler.sh "$PWD/ncc" 1     # run stage 1
```

```
===================Stage 1 Summary=================
12 successes, 0 failures
```

With the toolchain in place and both suites green, you are ready for
[stage 1](01-integers.md).
